# Chess Club (local-only)

Next.js 16 app, Bun for packages, Tailwind v4. The user deploys it to Vercel from their own GitHub repo; Claude never pushes, commits to a remote, or deploys.

- Data: behind the async storage layer in `src/lib/db.ts` (`readDb` is request-cached, `mutate` serializes writes and retries on version conflicts, `replaceDb` for import/restore, `listBackups`/`readBackup`). Without `DATABASE_URL` it is the JSON file `data/db.json` (override folder with `CHESS_DATA_DIR`) with daily snapshots in `data/backups/`; with `DATABASE_URL` (Neon Postgres on Vercel) it is one jsonb row in `club_state` plus `club_snapshots`, tables created on first use. `migrate()` upgrades old data on every read. Pages and actions must `await` every read and mutation.
- Ratings are derived: `recomputeRatings()` in `src/lib/elo.ts` replays all completed, non-forfeit games. Never update ratings by hand.
- Pairing logic: `src/lib/pairing.ts` (random / Swiss greedy with hard+soft rematch costs, color balancing incl. no-3-in-a-row, Berger round robin, bracket seeding).
- Knockout state lives in `tournament.knockout.matches`; `syncKnockout()` in actions keeps matches, tiebreak games and winners consistent after every result change.
- Read models: `src/lib/queries.ts` (standings + tiebreaks, crosstable, h2h, streaks, club stats, sessions, knockout placement).
- Mutations: server actions in `src/lib/actions.ts`; destructive ones call `requireAdmin()` (`src/lib/auth.ts`). Every exported action is wrapped in `run()` (form actions) or `attempt()` (called from client components). Throw `UserError` (`src/lib/errors.ts`) for anything the user should read: `run()` redirects back with `?flash=` which `Flash` shows as a toast; `attempt()` returns `{ error }`. Plain `Error` means a bug and hits `error.tsx`.
- Access: `src/lib/tokens.ts` signs stateless cookies for two roles (admin password → `cc_admin`, club-wide member code → `cc_member`, bound to the code's hash so a new code signs everyone out). `src/proxy.ts` redirects to `/join` when `settings.memberCodeHash` is set and no valid cookie is present; `/join`, `/admin` and `/api/*` are exempt. No code set = open club (local default). A third cookie `cc_me` (role "self", `playerId`) is the device identity, issued by `claimWithPin` only after the player's 4-digit PIN (`Player.pinHash`, scrypt; lockout fields + helpers in `src/lib/pin.ts`) is set or verified; `currentPlayerId()` in auth.ts reads it. Self-only actions (`setAvatar`, `changeOwnPin`) accept the claimed player or the admin; `resetPin`, `updatePlayer`, `deletePlayer`, `addPlayer` are admin-only; `registerSelf` lets an unclaimed device add exactly one player (itself) with a PIN. `/me` is the welcome/picker/PIN screen; `proxy.ts` sends devices without `cc_me`, `cc_skip` or `cc_admin` there once (skip cookie lasts 30 days).
- Activity log: call `log(db, text)` inside the `mutate()` that persists a change; `db.activity` keeps the last 500 entries, shown on the Admin page.
- Club layer: `src/lib/club.ts` (titles by rating band from `TITLE_GAMES` games, derived achievements, seasons + `seasonTable`, tournament winners, month champions, home highlights). `db.seasons` is the only stored state; `migrate()` opens a first season when none exists. Club identity lives in `settings.club`.
- Avatars: `Player.avatar` is a seed string; `face(seed)` in `src/lib/avatar.ts` derives a flat cartoon character (skin, hair style and colour, head shape, eyes, mouth, brows, accessory, shirt, ground colour) and `FaceSvg` draws it as SVG. `migrate()` seeds missing ones with the player id, `addPlayer` uses a random seed, the edit form offers `avatarChoices()`. `Avatar` in `ui.tsx` looks the seed up via a per-request `cache()` of `readDb()`, so `ui.tsx` must stay server-only.
- Layout: two-column pages use `grid gap-6 lg:grid-cols-[3fr_2fr]` with default stretch; a column that holds several cards is a `div.col-stack` (flex column, last card grows) so both columns end on the same line. `Section` is a flex column whose body grows.
- Visual language: display serif `font-display` (Fraunces) for h1/card titles, Geist for body; `KnightMark` logo and `Icon` line icons in `src/components/icons.tsx` (no unicode chess glyphs or emoji for UI chrome); `.board-texture` for the hero; medal `Rank` circles; `QuoteOfTheDay` (`src/lib/quotes.ts`, rotates by calendar day) instead of a motto. Do not put `<title>` inside SVGs (hydration mismatch); use `aria-label`.
- Routing: `src/app/layout.tsx` is html/body only; `src/app/(site)/layout.tsx` adds Nav, centered `main` and footer. Admin sign-in is reachable only by typing `/admin`; the header shows the Admin badge only while signed in.
- Pages are server components with `force-dynamic`; interactive bits (`ResultButtons`, `ConfirmButton`, `Toast`, `Flash`, `ThemeToggle`, `SearchBox`) are client components.
- Run: `bun run dev`. Check: `bun test` (unit tests in `src/lib/__tests__/`), `bunx tsc --noEmit`, `bun run lint`, `bun run build`. A second isolated instance: `CHESS_DATA_DIR=... NEXT_DIST_DIR=.next-e2e bun run dev -- -p 3001`.
